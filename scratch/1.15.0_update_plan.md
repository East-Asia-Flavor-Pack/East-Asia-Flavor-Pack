## 3. P0 — 실행 구조와 핵심 콘텐츠 연결

### P0-00. 시작 POP의 삭제된 문화 ID 수정

`common/history/pops/99_chi.txt`에 1.15 문화 정의에서 더 이상 찾을 수 없는 `culture = siberian`이 **3곳** 남아 있다. 바닐라 문화 정의는 `siberian → evenki`로 바뀌었고, 같은 세 지역의 새 바닐라 POP도 `evenki`를 사용한다. EAFP에 별도 `siberian` 문화 정의는 없다.

| EAFP 위치 | 주·소유국 | 현재 POP 수 | 적용 |
|---|---|---:|---|
| `99_chi.txt:250` | `STATE_NORTHERN_MANCHURIA`, `MCH` | 32,000 | 문화만 `evenki`로 변경 |
| `99_chi.txt:571` | `STATE_OUTER_MANCHURIA`, `MCH` | 67,800 | 문화만 `evenki`로 변경 |
| `99_chi.txt:583` | `STATE_AMUR`, `MCH` | 81,123 | 문화만 `evenki`로 변경 |

**완료 기준:** 활성 스크립트의 구 문화 ID 참조가 없어지고, 새 게임에서 세 POP의 문화·수·소유국이 의도대로 생성된다. [문화 정의][v-cultures], [동아시아 POP][v-pops-east-asia], [시베리아·외만주 POP][v-pops-siberia]

### P0-01. 저널 112개 정의를 1.15 구조로 점검·전환

범위: `common/journal_entries/*.txt` 전체. 구형 종료 필드가 없는 지속형·표시용 JE도 새 화면, 자동 활성화, 위젯 조건을 점검한다. 파일별 전체 목록은 부록 A에 있다.

| 기존 구조 | 1.15 적용 방식 |
|---|---|
| `complete` + `on_complete` | 성공 `outcome`의 `trigger` + `effect` |
| `fail` + `on_fail` | 실패 `outcome`의 `trigger` + `effect` |
| `invalid` + `on_invalid` | `flags = { hidden invalid_outcome }`인 `outcome`; 기존 무효화 조건·정리 보존 |
| JE 수준 `timeout = N` + `on_timeout` | **기간 `timeout = N`은 JE 수준에 유지**. 효과는 `flags = { timeout }`인 `outcome`에 배치. 이 outcome에는 `trigger`를 두지 않음 |
| `custom_completion_header` 등 | 해당 outcome의 `header`·`effect_header` |
| `event_outcome_completed/failed/timeout/invalidated_*` | 해당 outcome 내부의 `event_outcome_desc` / `event_outcome_effect_desc` |
| `on_*_all_involved` | contextless JE의 해당 outcome 내부 `effect_all_involved`로 이전할 필요가 있는지 확인 |

작업 순서:

1. **국가별 주요 흐름부터 한 묶음씩 전환한다.** 일본 유신·덴포·쇄국·홋카이도 → 청 아편전쟁·태평천국·군벌·통일 → 조선 동학·개혁·조청전쟁 → 몽골·베트남·조계·기타 고유 JE 순으로 진행한다.
2. 각 JE마다 기존 성공·실패·무효·시간 초과 조건, 보상, 다음 사건, 변수 삭제, modifier 제거를 대응표로 옮긴다. 숨겨진 정리를 일반 실패 보상과 합치지 않는다.
3. 모든 outcome에 `conclusion_desc`, 비숨김 outcome에 `header`와 `effect_header`를 둔다. 시간 초과 outcome과 무효 outcome은 각각 최대 하나다. `historical`은 실제 역사 경로에만 사용한다.
4. 성공과 실패가 동시에 참이 되는 상태를 조사한다. 표시 순서만으로 실행 우선순위를 추정하지 말고 조건의 배타성 또는 엔진 실행 결과를 확인한다.
5. `event_outcome_effect_desc`는 **표시용**이다. 보상을 여기에만 옮기거나 `effect`와 양쪽에서 실행하는 구조를 만들지 않는다.
6. 동적 스코프를 사용하는 JE 제목에는 필요시 `<je_id>_concluded` 정적 번역을 추가한다. 종료 후 남지 않는 인물·국가·변수에 종료 화면이 의존하지 않게 한다.
7. 새 `activation_description`, `dlc`, `map_color`, `map_tooltip`, `disable_evaluation`은 목적에 맞춰 적용한다. `dlc`는 표시 배지이며 실제 DLC 조건을 대신하지 않는다. `disable_evaluation`은 국가 형성·부활 뒤 JE가 필요해질 가능성이 없는 경우에만 사용한다.

- `eafp_first_opium_war.txt`: 영국·청의 승패가 서로 일치하고 후속 사건이 한 번씩만 실행되게 한다.

- `eafp_concessions_in_china.txt`, `eafp_scramble_for_korea.txt` 등: JE group에서 상속하는 context를 확인하고, contextless JE에서 국가 root를 가정하지 않는다.

**완료 기준:** 모든 활성 JE에서 이전 종료 필드의 잔여 사용을 검토 완료하고, 신규 게임에서 활성화→각 종료 경로→다음 사건→종료 목록 표시가 정상이다. 구문 변환만으로 완료 처리하지 않는다. [1.15 JE 문서][v-je-doc]

### P0-02. 왕조 상태를 `dynasty_var`로 통일

현재 모드에는 `dynasty_var` 사용이 없다. `house_tokugawa` 문자열은 10개 파일에 남아 있으며 템플릿 초기화, 무후계 쇼군 선출, 추방 제한, 유신 사건·운동에 걸쳐 있다.

| 용도 | 이전 | 적용 형태 |
|---|---|---|
| 왕조 지정 | `set_variable = house_tokugawa` | `set_variable = { name = dynasty_var value = flag:house_tokugawa }` |
| 왕조 판정 | `has_variable = house_tokugawa` | `var:dynasty_var ?= flag:house_tokugawa` |
| 황실 판정 | `has_variable = house_yamato` | `var:dynasty_var ?= flag:house_yamato` |

대상은 `eafp_japan_daimyo_templates.txt`, `eafp_japan_daimyo_effects.txt`, `eafp_japan_vanilla_succession_effects.txt`, `eafp_character_interactions.txt`, `zz_eafp_ideological_movements.txt`, `eafp_00_meiji_restoration.txt`, `events/000_eafp_japan_overrides.txt` 및 동일 변수의 나머지 실제 호출부다.

- 도쿠가와·야마토 외 왕조 이름도 검색하고 **바닐라가 이행한 왕조 상태인지 확인한 뒤** 바꾼다. `house_*`라는 문자열만 보고 번 식별자나 독립적인 모드 상태를 바꾸지 않는다.
- `daimyo_han_var`와 `daimyo_var`는 각각 번·주 식별 정보이므로 유지한다.
- 바닐라 `on_heir_born_inherit_royal_house_effect`가 새 값을 상속한다. 모드에 별도 후계 상속 훅이나 구·신 왕조 변수를 계속 동기화하는 루프를 만들지 않는다.
- 이이·미토·기슈·오와리 등 템플릿과 생성 분기를 함께 수정한다. 초기 인물만 새 값을 가지는 상태를 피한다.
- 기존 세이브 호환은 별도 과제로 둔다. 우선 신규 게임을 기준으로 전환하며, 구형 세이브 지원이 필요할 때에만 충돌 정책을 정한 일회성 이행을 설계한다.

**완료 기준:** 초기 인물·역사 템플릿 등장·무작위 후임·신생 후계가 같은 왕조 판정을 사용하고, 쇼군/황실 추방 제한과 유신 진영 선택이 유지된다. [일본 템플릿][v-jap-template], [후계자 상속 효과][v-on-action-effects]

### P0-03. 저널 종료, 사건 후처리, on_action 연결을 함께 이행

1. `events/000_eafp_japan_overrides.txt`, `heavenly_kingdom_events.txt`, `opium_wars_events.txt`, `boxer_rebellion_events.txt`, `warlord_china_events.txt`, `soi_events/00_ep1_korea_events.txt`의 대체 사건을 해당 JE와 묶어 검토한다.
2. 바닐라의 새 `je_*_cleanup`을 읽고 EAFP가 유지해야 할 변수·목록·modifier를 먼저 구분한다. 예를 들어 `je_heavenly_kingdom_main_cleanup`은 중국의 `cult_center`, `gold_transfer`, `gold_transfer_nil`을 지운다. EAFP의 후속 태평천국 흐름이 읽는 동안 호출하면 안 된다.
3. `je_meiji_restoration_cleanup`이 삭제하는 `cached_daimyo_loyalty`, `restoration_timer_var`도 같은 방식으로 판단한다. **후속 사건에서 사용할 데이터는 사건 선택·후처리가 끝나기 전에 삭제하지 않는다.** 빈 cleanup을 흉내 내기 위한 새 helper는 만들지 않는다.
4. `opium_wars_unresolved` 해제 등 새 바닐라의 실제 수정은 반영하되, EAFP 고유 제1차 아편전쟁 및 일반 아편전쟁의 책임과 수명을 구분한다.
5. `common/on_actions/00_code_on_actions_definition.txt`와 `eafp_japan_regional_on_actions.txt`는 기존 바닐라 훅에 모드 콜백을 연결한다. 1.15의 바닐라 effect를 통째로 복사하지 않고 실제 병합·호출 여부를 확인한다. 특히 `on_monthly_pulse_character`에는 모드의 분할 선언과 바닐라 임시 불사 해제가 함께 살아 있어야 한다.
6. 현재 모드에는 `on_journal_entry_completed`/`on_journal_entry_failed` 직접 등록이 없다. 새 이름의 빈 훅을 추가할 필요는 없다. 향후 공통 종료 훅을 쓸 때에는 `on_journal_entry_concluded`가 성공만을 뜻하지 않음을 반영한다.

**완료 기준:** 종료 효과·cleanup이 정확히 한 번 실행되고, 지연 사건 스코프가 유효하며, 반복 재등장과 영구 modifier 잔류가 없다. [cleanup 정의][v-cleanup], [on_action 정의][v-on-actions]

## 5. P2 — 경제·지도·GUI·문서·출시 표기

### P2-01. 구리 공급망과 새 법률의 경제 효과

- `common/history/buildings/{chi,jap,kor}_building.txt`, `common/buildings/eafp_chinese_water_system.txt`, `eafp_korean_reclamation.txt`, `eafp_monuments.txt`, `common/production_methods/`의 고유 PM을 점검한다.
- 새 `copper`·구리 광산 및 PM/PMG는 바닐라에서 상속한다. 산업 투입재 변화가 양무운동·일본 산업화·군수 생산·조계 세수 목표를 얼마나 바꾸는지 신규 게임의 부족 상품·가격·고용·수익으로 측정한다.
- 초기 건물의 PM ID가 존재하는지만 보지 말고 해당 건물의 PMG에 속하는지 확인한다. 임의로 모든 포병 공장을 청동포로 바꾸거나 구리 광산을 중복 생성하지 않는다.
- 해상 겨울 규칙 때문에 몽골·만주·홋카이도·조선의 경제/전쟁 진행이 달라질 수 있다. 고정 목표 수치 변경은 관측 결과가 있을 때 별도 균형 작업으로 한다.

### P2-02. 지도·초상화·문화·위젯

- EAFP에는 대상 바닐라와 같은 경로의 활성 지도 텍스트·GUI 파일이 없다. 동아시아 자원·추위·항구 변경과 새 저널 패널은 상속을 기본으로 한다.
- `common/history/states/chi_states.txt`의 주 생성·분할, 조계의 주 참조, 대만 원정과 항구 참조가 새 지도에서 여전히 유효한지 확인한다. 대만·도호쿠·류큐의 항구 위치 변경은 실제 화면에서도 확인한다.
- 일본 유신의 새 바닐라 지도 툴팁은 한 주에서 다이묘 한 명을 고르는 방식이다. 여러 번이 같은 주를 공유하는 EAFP에서는 그대로 가져오지 말고 기존 `daimyo_han_var`·지역 집계 설계와 일치시킨다. 지도 표시 추가는 필수 실행 호환성 이후의 UI 작업이다.
- `gui/journal_entry_widgets/`의 위젯과 `common/scripted_guis/`를 활성 JE에서 검증한다. 종료된 JE에는 custom widget이 표시되지 않는 새 규칙에 맞춰 결론 번역으로 필요한 정보를 제공한다.
- `common/genes/eafp_genes_accessories_clothes.txt`, `eafp_genes_accessories_headgear.txt`, `eafp_genes_korean_flavor.txt`의 `special_genes`는 이름만 같은 복합 선언이다. 새 바닐라 전체 gene 변경을 덮어쓰지 말고 실제 하위 gene/template 충돌과 인물 표시를 확인한다.
- 문화 5종의 실질 정의는 이번 최상위 교집합에서 변경 대상으로 나오지 않았다. 기존 이름 합집합·귀족 인명·인장을 보존하고, 일본 문화 생성 도구의 **1.15 입력 기반 `--check`**를 실행하여 주석·원본 해시 및 데이터 차이를 확인한다.

### P2-03. 문서와 배포 메타데이터

- 실제 이행 후 `.metadata/metadata.json`을 `supported_game_version = 1.15.*`로 변경하고 README·Steam 설명·changelog의 대상 버전을 맞춘다. 계획서 작성만으로 지원 완료를 선언하지 않는다.
- README의 기존 `documentation/1.14_beta_update_plan.md` 링크는 현재 파일 위치인 `scratch/1.14_beta_update_plan.md`와 맞지 않는다. 1.15 안내로 전환하면서 경로를 정리한다.
- `common/journal_entries/journal_entries.md`, `common/character_roles/character_roles.md`, `common/treaty_articles/treaty_articles.md` 등 구형 설명서는 1.15 원본과 비교하여 필요한 설명을 갱신한다. `documentation/` 원본 로그는 보존한다.
- EAFP의 일본 콘텐츠가 현재 전제하는 DLC 구성을 유지하고 새 IP5 기능과의 경계를 기록한다. 새 기능을 사용하면 존재하는 파일만으로 DLC 이용 가능성을 추정하지 말고 `has_dlc_feature` 조건과 비활성 환경을 확인한다.

- 수정하는 게임 텍스트는 저장소 규칙대로 UTF-8 BOM·CRLF를 유지한다. 한국어·영어·중국어 간체의 새 종료 설명·헤더·툴팁을 함께 추가한다.

## 6. 1.15 documentation에 근거한 API 판정

판정은 다음 세 층을 구분한다.

1. **엔진 명령:** `documentation/effects.log`, `triggers.log`에서 이름·지원 스코프·인자를 확인한다.
2. **데이터 구조·스크립트 정의:** JE의 `outcome`, 사건의 `fire_only_once`, scripted effect/trigger/value는 바닐라 대상 커밋 또는 모드의 실제 정의에서 확인한다. 엔진 로그에 없다는 이유만으로 무효로 판정하지 않는다.
3. **실행 가능성:** 이름이 존재해도 실제 root·target·saved scope·DLC 조건·호출 순서가 맞아야 한다. 이것은 정적 이름 대조와 별도로 검증한다.

### 문서 부재를 오류로 오판하면 안 되는 항목

- `set_temporary_event_immortality`, `revoke_temporary_event_immortality`, `country_is_valid_qing_treaty_partner`, `movement_radicalism_suppressed_after_civil_war`, `is_independent_and_not_being_subjugated`는 바닐라 scripted effect/trigger/value에서 찾는다.
- `any/every/random_state_in_dongbei`는 바닐라 documentation에 없지만, EAFP의 `common/geographic_regions/eafp_geographic_regions.txt`가 `short_key = "dongbei"`를 정의한다. 모드 로드 후 생성되는 지역 iterator로 검증해야 하며 삭제된 엔진 명령으로 취급하지 않는다.
- `state_pop_support_law_freedom_of_conscience_add`, `state_pop_support_law_total_separation_add`는 모드의 `common/modifier_type_definitions/eafp_modifier_types.txt`에 `REPLACE_OR_CREATE:`·`script_only = yes`로 정의되어 있다. 정의 존재는 확인했지만 **정치 지지도를 실제로 바꾸는 소비 경로까지 증명한 것은 아니다.** 필요시 별도 기능 감사 대상으로 둔다.
- `house_tokugawa` 자체는 엔진 API가 아니다. 이번 문제는 `set_variable`이 무효인 것이 아니라 바닐라가 읽는 데이터 구조가 바뀌었다는 점이다.
- `complete`·`on_complete` 등 JE 구조 필드는 effect/trigger 로그의 명령 목록으로 판단하지 않는다. 대상 JE 문서가 구형 구조의 대체를 명시하므로 `outcome`으로 이행한다.

### 이번에 수행한 정적 대조와 한계

- 활성 스크립트의 할당/비교 키와 1.15 문서의 명령 이름을 대조하여 effect **251종**, trigger **277종**의 이름 일치를 확인했다. 이는 스코프·매개변수의 전수 통과 판정이 아니다.
- 이전 EAFP documentation과 비교했을 때 사라진 이름 중 현재 호출부에 등장한 후보는 위 `dongbei` iterator 3종이었다. 이는 모드 정의로 설명된다. **이전 로그를 1.14의 정확한 엔진 명세로 가정하지 않으며**, 이 차집합만으로 1.15 변경 전체를 판정하지 않는다.
- 데이터베이스 정의의 삭제·이름 변경을 활성 스크립트의 식별자와 별도로 대조한 결과 `siberian` 문화의 POP 참조 3곳을 발견했다. P0-00에서 처리한다. 이는 effect/trigger 이름 검사가 잡지 못하는 객체 ID 문제다.
- 구 바닐라에서 존재했으나 새 바닐라와 모드 양쪽에 없는 scripted effect/trigger/value/list 이름을 현재 할당·비교 호출부에서 찾는 검사에서는 후보가 없었다. 동적 문자열·매개변수 치환·전체 타입 검증은 포함하지 않는다.
- `common/static_modifiers`의 단일 숫자값 할당 **1,224건**은 1.15 modifier 목록 또는 모드 modifier type 정의에서 이름을 확인했다. 적용 스코프·게임 기능·균형 검증은 별도다.
- GUI·현지화에서 추출한 `Type.Function` 형태의 함수명은 모두 `documentation/data_types*.txt`에서 검색됐다. 같은 이름이 다른 타입에 있을 수 있으므로 정확한 datacontext·인자·렌더링은 실행 검증 대상으로 남긴다.
- 위 결과는 **“명백한 API 이름 삭제가 주된 장애”라는 증거가 없다는 뜻**이다. JE schema, 왕조 데이터, callback 수명 문제를 해결하기 전 모드 전체가 호환된다고 결론 내릴 수 없다.

## 7. 전쟁·조약 관련 유지 사항과 기존 회귀 항목

### 1.14 대응에서 유지할 것

- 사상자 modifier의 `country_war_support_casualties_mult` 전환과 지지도 `50`·`75` 기준을 유지한다.
- 공세 스코프의 `add_diplomatic_play_war_support`와 전쟁 스코프의 `add_war_war_support`를 유지한다. 단순히 새 effect 이름이 보인다는 이유로 교체하지 않는다.
- `common/on_actions/eafp_code_on_actions.txt`의 최종 전쟁 목표 처리와 조계 부여·회수 책임을 유지한다. 타이머 훅에 같은 보상을 추가하여 두 번 적용하지 않는다.
- `eafp_grant_concession`은 현재 `flags = { can_be_enforced }`다. 새 문서상 재협상에 가져온 기존 조항의 entry effect 생략 규칙을 확인하되, 새로 추가된 조항은 실행되어야 한다. `scope:is_renegotiation`만 보고 모든 재협상 조항의 부여를 건너뛰는 처리는 잘못이다.
- 전쟁 지지도 범위와 API의 유효성은 확인됐지만, 봉쇄·점령 압력 및 악명 기준이 더 바뀌었으므로 기존 `+100`, `-200`, 고정 악명 5의 적절성은 실행 결과로 판단한다. `1.15` 호환성 작업이라는 이유만으로 일괄 수치 조정하지 않는다.

### 기존 계획서의 미완료 항목을 다시 확인할 것

1. `heavenly.4`와 `je_taiping_pre.on_timeout`에 태평천국 `+50` 가산이 각각 남아 있다. 이행 후에는 on_timeout이 outcome으로 바뀌므로 **실제 공세 생성 직후 한 번만 가산되는지** 확인한다. 앞의 호출이 아직 공세가 없는 시점인지도 스코프로 판단한다.
2. 생맥 사건은 발동 조건과 실제 조약항/소유국 추첨의 비전쟁·자기 국가 제외 조건을 일치시킨다. 바닐라 변경을 옮기는 과정에서 EAFP의 기존 미완료 수정까지 해결한다.
3. 이전 계획서에 기록된 `tools/validate_114_p0.py`, `validate_114_p1.py`, `validate_114_p2.py`는 현재 작업 트리에 없다. 과거 통과 기록을 현재 검사 결과로 재사용하지 않는다. 1.15용 검증이 필요하면 현재 구조에 맞춰 새로 작성한다.
4. `common/history/countries/`의 청·일본·조선·대월, `common/history/characters/`의 일본·조선은 두 바닐라 커밋 사이에 내용 변화가 없었다. 같은 경로를 덮는다는 이유만으로 시작 역사를 재복사하지 않는다. 인물 **템플릿** 변경은 별도 P1 작업이다.
