### 회귀 검사에서 함께 정리한 사항

- 현재 P0 커밋의 `heavenly.4.immediate`에 `+50` 가산이 남아 있었다. 실제 공세 생성은 여전히 60일 후 저널이 담당하므로, 사건의 이 가산만 제거하고 `je_taiping_pre.on_timeout`의 가산을 유지했다. 그 외 사용자가 보존한 주석·태평천국 처리 변경은 유지했다.
- 기존 조계 검증기의 두 오판을 수정했다. `is_shown_when_inactive`는 표시 조건으로 허용하고 자동 활성화 `possible`은 계속 금지한다. 도시 건물군은 바닐라 제조업 칙령과 같은 부모 그룹 매칭에 따라 자식 그룹까지 확장해 검사한다. 조계 게임 코드를 테스트에 맞춰 바꾸지 않았다.
- 일본 직위 검증기를 실제 `common/history/characters/jap - japan.txt`, 초기 이이 나오아키 템플릿의 지도자 지정, 히코네 번 식별자에 맞췄다. 직위 수명·정리·후임 모집 검사는 유지했다.
- 새 영구 변수·월간/주간 훅·공통 효과는 추가하지 않았다. 새 전쟁 목표는 엔진의 `re_establish_war_goal`이 요구하는 정의이며, 수동 정복 목록에서는 숨긴다.

- 통일 저널의 무효화는 중국 국가 수 감소/중앙정부 소멸에 대한 기존 정리 흐름을 유지했다. 별도 승패 변수·종전 추적기를 추가하지 않았다.
- 제1차 아편전쟁의 영국/청, 군벌 사건의 중화민국/청, 의화단의 기존 `+100` 다섯 호출은 유지했다. 엔진의 실제 초기 지지도와 균형을 측정하지 않은 상태에서 일괄 반감하지 않았다.

GitHub 연결에서는 해당 저장소 조회가 404를 반환했다. 따라서 위 원격 주소가 설정된 로컬 복제본에서 커밋 메시지·부모 SHA·파일 내용을 확인했다. 원격 최신 HEAD를 확인한 것으로 취급하지 않으며, 위 두 SHA에 한정한 분석이다. 로컬 바닐라 작업 트리는 깨끗했고, EAFP에 이미 있던 미추적 `scratch/yangyo_journal_design_plan.md`는 변경하지 않았다.

**우선순위는 전쟁 지지도 및 전쟁 목표 처리 → EAFP가 대체한 동아시아 콘텐츠 → 외교·종속국·AI 재검증 → 표시·문서·버전 정리 순서다.** 전체 바닐라를 복사해 덮는 방식은 필요하지 않다. EAFP가 덮어쓰지 않은 변경은 1.14 바닐라를 통해 적용되며, 덮어쓴 정의와 새 엔진 규칙에 의존하는 사용자 정의 콘텐츠를 집중 수정한다.

현재 모드에는 일부 1.14 변경이 이미 들어 있다. 일본 문화의 조약 인장과 메이지 유신파·도쿠가와 충성파의 내전 패배 후 급진성 억제가 대표적이다. 따라서 아래의 “변경된 바닐라 정의와 겹침”은 곧 “수정이 누락됨”을 뜻하지 않는다.

### 조사 범위와 한계

- `git diff -M` 기준 **1,283개 경로 변경, 59,493줄 추가, 25,000줄 삭제**. 수정 1,006, 이름 변경 224, 삭제 27, 추가 26건이다. 이름 변경은 한 건으로 센다.
- `common` 388, `events` 60, `gui` 59, `localization` 766, `map_data` 9, `gfx` 1건이다. 번역·이름 변경·공백 변경도 포함되므로 모두 독립적인 게임 기능 변경은 아니다.
- 활성 `.txt`의 최상위 정의를 비교하고 `REPLACE:`·`INJECT:` 접두사를 제거해 대조한 결과, **변경된 바닐라 정의와 겹치는 EAFP 정의 34개**를 찾았다. 단순 동일 경로 충돌은 `events/heavenly_kingdom_events.txt` 하나다.
- 위 34개 집계는 `common`과 `events`의 최상위 정의 비교이며, history 내부 객체·GUI 타입·엔진 제공 효과 전체를 해석한 결과는 아니다. 별도로 사용자 정의 전쟁 목표·조약·종속국·번역·호출부를 검색했다. `.disable`은 적용 대상에서 제외했다.
- 영문·한국어·중국어 간체의 바닐라 번역 변경 키와 현재 모드 번역 키를 대조했을 때, 기존 값이 변경된 동일 키의 교집합은 없었다. 다만 조청전쟁처럼 **모드 자체의 의미가 바뀌어 수정해야 하는 번역**은 있다.
- 이 저장소의 텍스트 diff로 엔진 내부 변경 전체나 실제 실행 결과를 확정할 수는 없다. 특히 기존 `documentation/*.log`에는 `has_war_exhaustion` 등 구형 API가 남아 있어 1.14의 최종 근거로 쓰지 않는다.

## 2. `1.13.8 → 1.14_beta`에서 확인된 변화

### 2.1 전쟁 지지도와 전쟁 종료 구조

1. **전쟁 지지도 범위가 `-100…100`에서 `0…100`으로 바뀐다.** `MIN_WAR_SUPPORT = 0`, 중립 수렴점 50, 자신감 기준 75, 저지지도 불이익 기준 25가 설정된다. `< 0`을 검사하는 기존 콘텐츠는 도달할 수 없는 분기를 갖게 된다. [바닐라 defines][v-defines]
2. `war_exhaustion_values.txt`가 삭제되고 `war_support_values.txt`가 추가된다. 전쟁 지속 기간, 전투 승패, 사상자, 황폐화, GDP 변화, 금 보유고·대출·파산, 종속국 태도, 충성파, 전쟁 목표 진행 등을 합산하는 **양수·음수 지지도 변화량** 계산으로 바뀐다. 누적 지지도와 주간 변화량을 구별해야 한다. [새 지지도 계산][v-war-values]
3. `country_war_exhaustion_casualties_mult`가 `country_war_support_casualties_mult`로 바뀌고, 전투 승패에 따른 지지도 증가·감소 modifier도 추가된다. 트리거 표시 정의는 `has_war_exhaustion`에서 `has_war_support_change`로 바뀐다. 구형 이름의 엔진 지원 여부와 스코프는 1.14 생성 문서로 최종 확인한다. [modifier 정의][v-modifiers], [트리거 표시 정의][v-trigger-loc]
4. 점령 타이머에 의한 **전쟁 중 목표 실현과 반대편의 대응 전쟁 목표 생성**이 명시된다. `fill_per_week`·`deplete_per_week`·`mirrored_wargoal`이 이를 제어한다. `mirrored_wargoal`이 없으면, 문서에 명시된 `assent_required` 예외 등을 제외하고 항복·협상 평화로만 실현된다. 따라서 사용자 정의 목표가 모두 자동으로 전쟁 중 실현된다고 가정해서는 안 된다. [전쟁 목표 문서][v-war-doc]
5. `on_wargoal_enforced_by_timer`가 추가된다. 타이머로 얻은 목표가 종전까지 유지되면 최종 `on_wargoal_enforced`도 호출된다. `on_won_war`·`on_lost_war`·`on_inconclusive_war`가 추가되고, `recently_won_war` 기록은 종전 훅으로 이동한다. [on_actions 변경][v-on-actions]
6. 방어 측의 기본 목표 설정이 `DEFAULT_WAR_GOAL = ""`로 바뀐다. 모드의 사건 전쟁이 기존 기본 목표를 전제하는지 확인해야 한다. [바닐라 defines][v-defines]

## 3. 현재 모드에 적용할 작업

우선순위 정의: **P0**는 실행 오류·도달 불가능 분기·보상 중복을 막는 호환성 작업, **P1**은 바닐라 수정 반영과 핵심 콘텐츠 동작 검증, **P2**는 표시·경제 균형·출시 정리다. “검증” 항목은 확인 결과에 따라 수정하며, 조사 대상이라는 이유만으로 새 패치를 추가하지 않는다.

### P0-01. 구형 전쟁 modifier와 트리거 정리

대상:

- `common/static_modifiers/eafp_chi_modifiers.txt:69,1516`
- `common/decisions/eafp_arrow_incident_decision.txt:38`

작업:

1. `taiping_taiping_rebellion`의 `+0.25`, `xinhai_revolution_army_modifier`의 `-0.9`를 새 `country_war_support_casualties_mult`로 옮긴다. 새 계산도 사상자 항에 `(1 + modifier)`를 곱하므로 **우선 부호는 유지**하고 효과 강도는 따로 검증한다.
2. `taiping_taiping_rebellion`은 `INJECT`이다. 바닐라의 새 필드와 합쳐진 최종 값이 의도한 `0.25`인지 확인하고, 같은 항목을 두 번 적용하지 않는다.

4. 1.14 실행 파일로 생성한 trigger/effect 문서에서 실제 지원 이름·인자·스코프를 확인한다. 구형 API의 완전 삭제를 텍스트 표시 정의만으로 단정하지 않는다.

완료 기준: 활성 스크립트에 구형 modifier가 없고, 애로호 AI가 해당 분기에서 오류 없이 판단하며, 태평천국·신해혁명 사상자 보정이 한 번만 적용된다.

6. 태평천국의 `recently_won_war`·`recently_lost_war` 소비 조건을 새 종전 훅의 기록 시점과 맞춘다. 바닐라가 기록하는 상태를 EAFP 월간 훅에서 다시 만들지 않는다.

완료 기준: 점령→목표 실현→재점령→최종 평화, 외교 요구 수락, 항복을 각각 재현했을 때 보상·팽창주의 진행도·조계 수입/권리 정리가 중복되거나 누락되지 않는다.

## 5. 조사 결과를 적용할 때 지킬 원칙

- `REPLACE`는 새 바닐라 변경이 가려지므로 해당 정의의 의미 차이를 합친다. `INJECT`는 해당 필드와 최종 병합 결과만 검사한다. on_action의 동명 정의는 일반 객체와 합성 방식이 같다고 가정하지 않고 실제 실행으로 확인한다.
- 새 변수를 기본 해결책으로 추가하지 않는다. 기존 전쟁·조약·주 소유권과 기존 EAFP 상태를 먼저 사용한다.
- 바닐라 수정이 이미 반영되어 있으면 보존한다. 특히 일본 정치운동, 일본 인장, 조계 입력 검증 스코프는 중복 이식하지 않는다.
- 사용자 정의 흐름이 바닐라와 다르면 수정의 목적을 이식한다. 중국 통일 저널처럼 다른 구조에 바닐라 `complete`를 복사하면 EAFP 기능이 사라질 수 있다.
- 확정 소스 변경, EAFP에서 확인한 잔존 코드, 새 균형 설계안, 실행 검증이 필요한 가정을 구별해 작업 기록을 남긴다.
